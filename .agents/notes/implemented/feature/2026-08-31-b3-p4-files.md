# Agent Note: B3-P4 Files — session-addressed read-only workspace access

Status: implemented

English | [中文](2026-08-31-b3-p4-files.zh.md)

## Problem

The Workbench had no way to look at the project files around a session. The existing `host.listDirectory` is a Host-level arbitrary-path browser for the directory picker — exactly the "host path as arbitrary read handle" the B3 foundation forbids for a Files surface. What was missing was a session-addressed read-only face: requests rooted at the session's project cwd, served through the composed filesystem capability so provider, sandbox and permission semantics apply, with containment, size, binary and cancellation boundaries enforced at the seam.

## Decision

**A new `fs.*` RPC domain in the gateway** (`packages/host/apiproxy`): `fs.listDir` and `fs.readText`, both taking `{ sessionId, path }` where `path` is RELATIVE to the session's project cwd ('' = the root). The implementation resolves the session (attached or cold) for its header cwd, resolves the workspace root and the requested target through `ctx.fs`, enforces canonical containment (`fs.contains`) with `fs-outside-workspace` for escapes, and then delegates to the provider's own `stat` / `listDir` / `readText` — binary rejection and permission failures surface as the backend's `FsError` codes mapped onto the wire (`fs-not-text`, `fs-permission-denied`, `fs-sandbox-denied`, `fs-io-error`, `fs-not-found`, `fs-not-directory`, `fs-not-regular-file`). `fs.readText` pre-checks `stat.size` against a 512 KiB bound (`fs-too-large`) before reading; aborts map to `cancelled`. A session without a project cwd is not served. The wire codes joined the closed `RpcErrorDetailsMap` and its schema branch; the client-side carrier (`IApiClient`, `AbstractApiClient`, the connection fixture) gained the domain so the official wire envelope stays the only client path.

**The Workbench Files panel** (`apps/desktop/workbench-plugin`): a `conversation.view` tab (id `files`, after the official chat and trajectory) rendering a lazily-expanded directory tree rooted at the current session's cwd (`useSessions` summary), a restricted text preview, localized error copy per wire code, and an `@file` copy button emitting the official mention grammar (`formatFileMention`) for the composer. Each `(sessionId, cwd)` view owns one request generation and AbortController: changing either value or unmounting aborts outstanding list/read calls, clears the generation's pending paths, and prevents every late success, failure, or `finally` from touching the new view. The panel talks to the gateway through the standard JSON-RPC envelope (`/api/fs.*`) — the same protocol the official client uses, no private DTO — and holds no host path: the tree's root is always the session's cwd, and a session switch issues its own root request immediately.

## Alternatives considered

**Reusing `host.listDirectory` / adding a host-path read.** That is the arbitrary-read shape the foundation names as the anti-pattern; the picker stays the picker.

**A DeepSeekGUI-side second filesystem implementation (Electron fs).** The B3 rules forbid an Electron read fallback and any second implementation; the gateway route through `ctx.fs` means a replacement provider serves the same interface unchanged.

**A generated Typert Remote for the fs capability.** The generated `remote` seam exists for capability domains; the gateway's unary RPC table is the established session/host contract surface and the smaller change — one domain file pair plus the mechanical map/schema/carrier rows.

## Consequences

The Files panel is the first consumer of a session-addressed FS face, and the gateway now carries the fs error vocabulary on the wire. The panel renders real provider semantics (sandbox, permissions, remote backends) with no host-path escape hatch; a composition without a filesystem capability answers a clear internal error rather than pretending. Request generations prevent one Session's file names, previews, or errors from appearing after another Session becomes current. The fixture and test fakes gained a stub `fs` domain (explicit failure — the fixture models no filesystem). The 512 KiB read bound is a gateway constant; a future larger bound is one constant, not a second read path.
