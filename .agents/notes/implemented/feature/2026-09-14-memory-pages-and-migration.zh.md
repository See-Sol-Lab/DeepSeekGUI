# Agent Note: 记忆页面与明确的迁移

Status: implemented

[English](2026-09-14-memory-pages-and-migration.md) | 中文

## 问题

工程记忆已经有了存储、工具、逐步召回和跨窗链路（[条目](2026-09-13-engineering-memory-entries.zh.md)、[Harness 一面](2026-09-13-engineering-memory-harness-face.zh.md)、[跨窗](2026-09-14-memory-cross-window-and-continuation.zh.md)），但没有人能看见它：记忆视图仍渲染旧的项目文件，「设置 → 全局记忆」还是 JS 设置插件里编辑旧 `memory.md` 的编辑器，注入模式没有人能够到的开关，可审阅的导入也没有页面。这一切要在不引入第二条数据路径的前提下交到用户手里——页面、会话工具与自动记录写同一份存储——而旧 Markdown 文件在用户另作选择之前仍是记忆，绝不与条目并行注入，绝不被页面修改，也绝不被悄悄退回。

## 决策

页面放在 DeepSeekGUI workbench 插件的客户端（`apps/deepseekgui/workbench-plugin/src/client/memory/`）：它在 inspector 命名空间旁挂载生成的 `workbenchMemory` Remote 命名空间，并对转发的 `workbench-memory/change` 只订阅一次，任何窗口的写入都让每个已挂载的页面重读。两处注册：记忆视图（`conversation.view` `deepseekgui-memory`，order 23）与「设置 → 全局记忆」（`settings.section` `deepseekgui-memory`，order 43）——后者接管 JS 设置插件原先注册的 id，那边的记忆分区与文案被删掉，一个 id 只有一个主人。

两个页面都跟随存储的 `injection` 模式。`entries` 模式下，视图先显示本会话的模型看到了什么——最近一份召回清单的 id、版本与范围，读自 Chat 窗口里那条注入上下文行（会话日志自己的 `source`），每条旁边是它现在的内容或「现已遗忘」——然后经同一个组件 `MemoryEntries` 显示本项目加全局的条目：搜索与类型筛选（带 `text` 的防抖 `list`）、含来源、会话、依据与修改历史的详情、编辑（内容、关键词、类型）、遗忘、撤销最近修改、带显式恢复的已遗忘条目，以及一个小的添加表单；随后是项目旧文件的可审阅导入和折叠起来的旧文件本身。设置页显示模式面板，`entries` 模式下再用同一个组件显示全局范围，加上 `<home>/memory.md` 的导入和把条目导出成 Markdown 文本供复制。`markdown` 模式下视图照旧渲染旧文件并提示切换入口，设置页显示旧编辑器——移植成 TypeScript：文本来自桌面控制模型，保存经封闭的 `save-global-memory` 命令连同编辑起点的文本一起提交，文件在底下被改过则被拒绝——外加导入。`off` 模式下两个页面都只有一句说明，不再读取任何东西。

写入引用页面读到的版本：过期版本以带当前版本的 `MEMORY_CONFLICT` 返回，显示为冲突并提供重新载入，绝不显示为完成；被拒绝的添加显示存储的错误码与信息；存储回答之前绝不显示「已保存」「已遗忘」「已恢复」「已切换」。打开的草稿所属的条目在别处变了（变更扇出重读了列表）时，草稿文本保留并如实说明。每次读写都按发出时的目标键控——列表按范围、视图按会话、导入按来源——再加一个代次计数，目标已经变化后才到达的结果绝不落地。模式切换是就地两步：按钮展开一段确认，说明什么会变、什么会留（旧文件保留但不再注入；条目保留且可切回；关闭不注入任何东西也不回退），然后才 `setInjection`；两条路径绝不同时生效，因为宿主的注入模式是唯一事实。导入先预览不写入，已在库中的段默认不勾，按序导入勾选的段并报告停在哪里，再重读预览让已落库的段显示为已存在；导出只生成文本并复制到剪贴板——没有任何代码路径写旧文件。接续记录的编解码挪到客户端安全的导出（`@deepseek-ai/dsh-workbench-memory/continuation`，用 `TextEncoder` 代替 `Buffer`），详情因此能把一份交接的五个部分分开渲染。

## 考虑过的替代方案

**单独的记忆客户端插件。** 拒绝：记忆视图本来就在 workbench 插件里，它挂着 remotes 并持有旧编辑器需要的桌面桥；一个插件、一条 overlay 行。

**保留 JS 设置分区、旁边再加一个 TypeScript 分区。** 拒绝：同一 id 两份注册，且旧编辑器会成为全局记忆路径的第二个主人；整段搬家。

**把导出写进旧文件或写在它旁边。** 拒绝：指令禁止后台反向写入，原文件旁再放一份就是第二个事实源；供复制的文本才是诚实的导出。

**解析召回清单的正文来显示用了什么。** 拒绝：注入消息的 `source` 已经记录了 id 与版本；页面读它再向存储要当前内容，「此后变过」与「现已遗忘」因此是事实而非解析。

**页面自己解析项目。** 拒绝：视图拿 inspector 已报告的会话文件夹去问存储的 `projectScope`，页面与工具对项目键的看法因此一致。

## 后果

客户端测试（jsdom + testing-library）分别覆盖各部件与视图：经存储列出与搜索；含来源、依据、会话在列与「来源会话已删除」的详情；引用读到版本的编辑、过期时的冲突与重新载入、底下变化时保留的草稿、空内容的拒绝；撤销、遗忘、恢复；添加与被拒绝的添加；范围已变后才到达的读取被丢弃；模式面板只在确认后切换并报告拒绝；旧编辑器的 CAS 保存与拒绝；导入的预览不写入、重复项不勾、应用与停止报告；导出的文本与复制；「本轮用了哪些记忆」块的「现为 v2」与「现已遗忘」；三种模式下的视图与设置分区；插件入口以存储属性注册视图、以 JS 插件原先的 id 注册分区。真实页面检查——中英、空列表、长条目、窄窗口、键盘操作、来源展开、导入错误，以及技能两个入口的回归——归监工窗。
