# Agent Note: 建立在存储域上的带版本工程记忆条目

Status: implemented

[English](2026-09-13-engineering-memory-entries.md) | 中文

## 问题

DeepSeekGUI 的记忆是两份扁平 Markdown 文件——`<home>/memory.md` 与 `<文件夹>/<文件夹名>.memory.md`——每个会话整篇读一次，按文本编辑。里面没有任何可寻址的东西：一条事实不重写文件就改不了，一行错的内容没法以「下个会话不再看到」的方式忘掉，一个窗口的编辑会悄悄覆盖另一个窗口的编辑，没落盘的「已保存」和落了盘的看起来一样。B7 记忆主线需要人与助手都能指着说的条目——记住、纠正、遗忘、撤销——一个存储权威、项目隔离、诚实的冲突，以及把现有文件搬过来而不把标题冒充成事实的办法。

## 决策

`packages/api/workbench-memory` 拥有一个存储域 `deepseekgui_memory`，用投影缓存已经在用的 `per-record` 布局：每个条目一个 JSON 文档放在 `<home>/storages/deepseekgui_memory/entries/`，被遗忘的副本放在 `forgotten/`，注入模式放在全局槽。不加第二个数据库、不做向量、不接陪伴 Core：条目就是几百个存储后端本来就原子发布的 JSON 文件。

条目是支撑三种编辑的最小记录：稳定的 `m_<12 位十六进制>` id、作用域（`global`，或带技能管理器项目键的 `project`——规范文件夹路径的 sha256，所以两个都叫 `proj` 的文件夹是两个项目）、闭合的 `kind`（`fact` / `preference` / `continuation`）、正文与关键词、来源 `source`（谁、来自哪个会话、何时、依据什么）、单调的 `version`、记在 `revised` 里的最近修改，以及记在 `previous` 里的修改前状态。纠正必须带上读到的版本；存储版本不同则回答带当前版本的 `MEMORY_CONFLICT`，写入在服务内串行，所以两个窗口编辑同一条目不会丢更新——输的一方重读。来源事实从不被覆盖：纠正的来源追加进 `revised`。撤销退回 `previous` 一层，并让被撤销的状态成为新的 `previous`，所以撤销两次就是重做。遗忘把整条移到 `forgotten` 表并在 `entries` 里留下墓碑；所有读取、检索和撤销只看 `entries`，正文从墓碑起就不再出现，过期窗口的纠正回答 `MEMORY_FORGOTTEN`，`restore` 是单独的显式方法，没有任何东西会自动调用它。每次写入只在域的持久化 put 之后返回；后端失败回答 `MEMORY_IO`，内存态不变。

旧文件经审阅后导入：`previewImport` 把文件按标题路径切成段落、列表项（带续行）与围栏块，标出正文规范化后已存在于目标作用域的段，且不写任何东西；`applyImport` 按顺序写入所选的段，`source.kind = 'import'`（文件与标题在 `detail`，行号在 `evidence`），跳过重复，接受编辑，并在第一处失败停止并报告已写入的部分。文件本身从不被修改。全局槽保持 `injection: 'markdown'`：本阶段只是数据能力，旧文件仍是会话读取的记忆，没有任何后台同步 Markdown 与条目。

## 考虑过的替代方案

**经 `storage-sqlite` 用 SQLite。** 不采用：它不在发行版的运行时闭包里，建在它上面的会话索引是派生的 `:memory:` 库，条目量级也不需要；per-record JSON 可读且本来就原子。

**在 Markdown 文件里编辑条目。** 不采用：文本文件里没有稳定身份，冲突、遗忘与撤销都无从表达；文件留作导入来源，并在迁移切换前仍是实际使用的记忆。

**纠正时覆盖来源。** 不采用：「这最早是谁说的」正是纠正被证明有误时人需要的；来源保留，纠正的来源追加。

**遗忘时硬删除。** 不采用：仍持有旧版本的窗口会在下一次写入时把正文重建出来；墓碑让那次写入成为可见的冲突，搁置的副本让恢复成为显式可审阅的动作而不是猜测。

**按标题一条一事实导入。** 不采用：一个标题可能覆盖几条事实或半条；预览给出结构段落供审阅，应用只写人选中的。

## 后果

测试在临时 home 上驱动真实存储栈：条目重启后读回逐字节相同；全局、一个项目、另一个同名文件夹的项目与合并视图互不干扰；两个并发纠正恰好一成功一 `MEMORY_CONFLICT`；后端拒绝的写入报告 `MEMORY_IO` 且读到的状态不变，包括墓碑写失败时把副本取回的遗忘；被遗忘的条目从 `get`、`list` 与文本检索里消失、拒绝过期纠正、只经 `restore` 回来；导入标出重复、保留文件、跳过已有内容、中途停止并给出已写 id。Remote 面已为工具阶段与页面准备好，但目前没有任何会话看得到条目——注入开关、工具与界面是后续阶段的工作。
