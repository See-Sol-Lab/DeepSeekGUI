# Agent Note: B3-P4 Files — 会话寻址的只读工作区访问

Status: implemented

[English](2026-08-31-b3-p4-files.md) | 中文

## Problem

Workbench 之前没有办法查看会话周边的项目文件。现有 `host.listDirectory` 是目录选择器用的 Host 级任意路径浏览——正是 B3 地基为 Files 表面明令禁止的「宿主路径当任意读取句柄」。缺的是一个会话寻址的只读面：请求以会话项目 cwd 为根，经组合的 filesystem capability 服务，让 provider、沙箱与权限语义生效，并在接缝处施加 containment、大小、二进制与取消边界。

## Decision

**网关新增 `fs.*` RPC 域**（`packages/host/apiproxy`）：`fs.listDir` 与 `fs.readText`，均接收 `{ sessionId, path }`，其中 `path` **相对**会话项目 cwd（'' = 根）。实现解析会话（热或冷）取 header cwd，经 `ctx.fs` 解析工作区根与目标路径，强制规范化 containment（`fs.contains`，越界回答 `fs-outside-workspace`），然后委托 provider 自己的 `stat`／`listDir`／`readText`——二进制拒绝与权限失败以 backend 的 `FsError` 码映射到 wire（`fs-not-text`、`fs-permission-denied`、`fs-sandbox-denied`、`fs-io-error`、`fs-not-found`、`fs-not-directory`、`fs-not-regular-file`）。`fs.readText` 读取前用 `stat.size` 预检 512 KiB 上限（`fs-too-large`）；取消映射为 `cancelled`。没有项目 cwd 的会话不予服务。wire 码进入封闭的 `RpcErrorDetailsMap` 及其 schema 分支；client 侧 carrier（`IApiClient`、`AbstractApiClient`、connection fixture）同步新增该域，官方 wire 信封保持唯一 client 路径。

**Workbench Files 面板**（`apps/desktop/workbench-plugin`）：一个 `conversation.view` 标签（id `files`，排在官方 chat 与 trajectory 之后），渲染以当前会话 cwd 为根的懒加载目录树（`useSessions` summary）、受限文本预览、按 wire 码本地化的错误文案，以及一个按官方 mention 语法（`formatFileMention`）复制 `@file` 引用的按钮供 composer 使用。每个 `(sessionId, cwd)` 视图拥有一个请求 generation 与 AbortController：任一值变化或组件卸载都会取消尚未结算的 list/read、清空该 generation 的 pending path，并阻止所有迟到的成功、失败或 `finally` 修改新视图。面板经标准 JSON-RPC 信封（`/api/fs.*`）与网关通信——与官方 client 同一协议，没有私有 DTO——且不持有宿主路径：树的根永远是会话的 cwd，切换会话后立即发起自己的根请求。

## Alternatives considered

**复用 `host.listDirectory` 或新增宿主路径读取。** 那正是地基点名的任意读取形态；选择器保持是选择器。

**DeepSeekGUI 侧第二套文件系统实现（Electron fs）。** B3 规则禁止 Electron 读取 fallback 与任何第二实现；经 `ctx.fs` 的网关路由意味着替换 provider 后同一接口原样服务。

**为 fs capability 生成 Typert Remote。** 生成的 `remote` 接缝面向 capability 域；网关的 unary RPC 表是既定的 session/host 契约面，改动更小——一个域文件对加机械的 map/schema/carrier 行。

## Consequences

Files 面板是会话寻址 FS 面的第一个消费者，网关的 wire 上从此携带 fs 错误词汇。面板渲染真实 provider 语义（沙箱、权限、远端 backend），没有宿主路径暗门；没有组合 filesystem capability 的组装回答明确 internal 错误而非假装成功。请求 generation 防止一个 Session 的文件名、预览或错误在另一个 Session 成为当前项后出现。fixture 与测试 fake 新增 stub fs 域（明确失败——fixture 不建模文件系统）。512 KiB 读取上限是网关常量；未来放宽只是一个常量，不是第二条读取路径。
