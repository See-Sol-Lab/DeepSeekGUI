# Agent Note: 审阅后整目录安装的技能库

Status: implemented

[English](2026-09-13-skill-library-install-management.md) | 中文

## 问题

DeepSeekGUI 的用户手里的技能是目录、下载的 ZIP 和单个 Markdown 文档，此前没有办法把它们装进桌面，只能手工复制到官方根目录——那里的一切对每个会话立即可见，复制到一半的包会被原样捡起，没有元数据头的文档被静默忽略，也没有任何记录说明技能从哪来。B7 方案把安装（桌面自己的技能库）与启用（按项目选择）分开，先要安装这一半：清单、写入前先审阅的导入、要么完整要么什么都不留的整包安装，以及碰不到自己安装范围之外的卸载。

## 决策

宿主包 `@deepseek-ai/dsh-skill-manager` 拥有 `<DSH_HOME>/deepseekgui/skills/<installId>/` 下的技能库——每个安装一个目录，装着完整的包和一份 `deepseekgui-skill.json` 清单（schema 版本、安装标识、名称、说明、来源、时间、文件数）。`skillManager` Remote 命名空间有四个方法。`inventory` 每次调用都从磁盘读技能库（切换 DSH home 时随之移动），把受管安装（带重新校验的状态）与管理器绝不删除的孤儿目录分开，并用 provider 自己的元数据规则扫描官方用户根与随包根，只读列出。`previewImport` 加载目录（遍历，链接跳过并报告）、ZIP（用 `fflate` 在内存中读取；带 `..`、绝对路径或盘符前缀、反斜杠、控制字符或以点结尾的条目一律拒绝；写任何文件前先限制解压体积）或 `.md`，然后找候选：根 `SKILL.md` 是持有整个包的一个候选，否则三层以内的嵌套 `SKILL.md`，再否则根层的 Markdown 文件。每个候选携带声明的名称与说明、对缺项的建议（由文件名或目录名得到的 kebab-case、正文第一个普通行）、分成可补齐（名称、说明）与阻断（旧的调用字段、非法布尔值、解析不了的元数据头）两类的问题，以及它将替换的现有安装——先按来源匹配、再按名称匹配，并以安装标识加来源返回，让页面点名实际目标。`applyImport` 逐条独立安装：在 `<DSH_HOME>/deepseekgui/skills-staging/` 下暂存完整目录（只有元数据变化时才重写 `SKILL.md`；其余照抄），写入清单，重新校验暂存的 `SKILL.md`，再重命名进技能库为 `<name>-<8 位十六进制>`；已确认的 `replaces` 保留安装标识与首次安装时间，旧目录先停到暂存区、交换失败则放回；任何失败都删除暂存目录并报告带码的问题。名称唯一性在 apply 时对照客户端确认的安装标识执行，绝不去按名称查找。`uninstall` 先把目录重命名进暂存区再删除，且只在清单写着该标识时动手。写操作串行；每次变化发出 `skill-manager/change`。包内任何内容都不执行，不安装依赖。

页面是单独的客户端插件 `@see-sol-lab/deepseekgui-skills`，以与其它分区相同的 launcher overlay 模式注册为第六个 DeepSeekGUI 设置分区（**技能（本地）**，order 45）；宿主服务由 web-app bundle 与 workbench inspector 并列挂载。它渲染清单，驱动审阅——名称与说明可编辑的候选、按码本地化的问题、替换目标——以及带行内确认的卸载。选择来源经一条新的桌面命令 `skill-pick-source { kind }`：打开系统对话框并把路径放进控制模型；不在桌面窗口内时页面接受手动输入的路径。页面上没有项目勾选：技能库刻意不是官方 provider 的根，在后续阶段的项目选择为它注册 provider 之前，安装对任何会话都不可见。

## 考虑过的替代方案

**直接复制进 `~/.dsh/skills`。** 不采用：那个根每个会话都扫，安装就等于启用，管理器也分不清自己的文件和用户的。

**现在就为技能库注册 provider。** 不采用：项目选择及其按项目存储是下一阶段；没有它的 provider 会把每个安装广播给每个会话。

**apply 时按显示名匹配替换目标。** 不采用：两个来源可以声明同一个名称；目标必须是那个人在审阅里看到的安装标识。

**原地自动修补来源文档。** 不采用：建议只写入库里的副本；下载件保持收到时的样子。

**直接解压进技能库。** 不采用：解压失败会留下一个未来 provider 当作技能的目录；技能库之外的暂存加最后一步重命名让根目录里没有半份条目。

## 后果

用户从技能所在的地方安装技能包，写入前看得到确切要写的内容；同名冲突是显式的；卸载限定在管理器自己的目录。技能库的身份模型（来源加安装标识）就是后续阶段给项目选择做键的东西，替换不会丢启用状态。ZIP 内的符号链接不保留（读取器拿不到链接属性），文件在体积上限内整份复制。`packages/api/skill-manager/tests` 的单元覆盖驱动了元数据规则、归档安全、清单与孤儿分类、嵌套与 Markdown 候选、建议、替换与同名规则、暂存失败、卸载拒绝和切换 home；插件测试覆盖审阅草稿、桥命令和页面对假命名空间的各条流程。Typert 生成、插件打包与组合装配由验收跑验证。
