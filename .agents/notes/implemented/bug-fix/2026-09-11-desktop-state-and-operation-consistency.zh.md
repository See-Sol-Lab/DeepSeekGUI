# Agent Note：桌面操作保持确认目标，并如实报告完成状态

Status: implemented

[English](2026-09-11-desktop-state-and-operation-consistency.md) | 中文

## 问题

对话框、轮询、子进程和文件操作异步结束。复用旧目标或把尝试操作当作完成，可能覆盖新数据或显示错误状态。

## 决策

Home 迁移校验清单路径、实际目录关系，并在清理旧副本前检查源文件摘要。停止 Harness 后失败时尽量恢复服务，并保留实际错误。Home 指针采用原子写入。会话导入先在临时目录完成副本，拒绝不可读的发现结果，并跳过已删除 ID。

启动状态落盘成功之后才报告启动完成。退出失败也会释放在途标记。延迟回调保留所属进程或 Home 身份。插件及权限确认不能授权另一个 Home；插件写入或迁移期间拒绝冲突的桌面操作。异步命令失败会返回发起操作的控制通道。子进程取消失败时保留活跃进程及其占用的槽位，直到进程实际退出。

Git 路径使用字面路径匹配。还原前核对已批准的补丁；推送使用真实目标的不可读证明，展示的 URL 和诊断内容会隐藏凭据。子进程超时后即使退出码为零，也仍报告失败。PR 正文通过 stdin 传入。工作台区分无法读取的 worktree 状态与干净状态，部分暂存文件在两组中分别显示，切换会话时重置项目局部显示状态。

更新检查缓存位置、平台、版本、大小和摘要。释放清单生成支持同版本的 Windows 和 Linux x64 安装包，并重新检查已记录摘要。取消安装保留已校验的下载；确认后再次检查完整性。浏览器操作在审批后复查取消状态和目标，失效或歧义引用会明确失败，启动失败会释放资源。终端输入与尺寸调整使用 JSON 行，管道分块不会改变命令；shim 参数保留路径中的空格和 shell 特殊字符。

全局记忆保存会比较打开时的 Home 和原文，再替换文件。记忆注入只读取有上限的 UTF-8 前缀，区分文件不可读与不存在。模板文件采用排他创建。设置页拒绝过期轮询结果，流式显示在原文被替换后保留新的完整文本。

## 影响

每项检查都对应具体的异步交接、文件写入或子进程结果，不引入自动重试或第二个运行时。源码 review 和不输出产物的类型检查不能证明安装包行为，释放前仍需针对性的运行时及安装验收。

## 考虑过的替代方案

仅在点击按钮时检查，无法保护确认到写入之间的间隔；只看零退出码会漏掉已超时的操作。自动重试可能重复写入，因此采用明确的目标检查和失败报告，由原有拥有者管理一次操作。
