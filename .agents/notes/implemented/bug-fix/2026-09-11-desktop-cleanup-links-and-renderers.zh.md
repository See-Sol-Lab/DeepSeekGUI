# Agent Note: 桌面清理保留链接目标并释放崩溃渲染器

Status: implemented

[English](2026-09-11-desktop-cleanup-links-and-renderers.md) | 中文

## 问题

Electron 的渲染器崩溃后，WebContents 仍可能存活。复用该目标会让内置浏览器无法使用。目录清理还涉及另一项归属问题：会话目录和迁移后的 Harness Home 可能包含指向数据范围之外的 junction。NSIS 的[递归删除实现](https://github.com/kichik/nsis/blob/master/Source/exehead/util.c) 进入目录条目前并不检查重解析点标记。

## 决策

桌面端在崩溃事件派发结束后释放浏览器面板，并确认窗口仍持有发生崩溃的那块面板。下一次浏览器操作再创建新面板。面板的隔离 Session 将回环地址请求交给 SSRF 代理，包括重定向中的请求。

会话清理通过文件系统元数据识别目录链接，只删除链接本身。卸载清理在枚举目录前检查 Windows 重解析点属性，对链接使用非递归删除。迁移路径先规范化再排除盘符根目录；清理不完整时明确报告，并在数据清理失败时保留位置记录。

## 备选方案

**把未销毁的 WebContents 视为健康的渲染器。** Electron 会在渲染器崩溃后保留 WebContents，因此该检查无法判断面板是否可用。

**递归删除时不检查链接。** 数据目录的名称不能约束 junction 指向哪里，删除操作必须落实这一区分。

**崩溃后自动重启浏览器。** 释放失效目标已经足够；重建由下一次用户或工具请求触发，避免反复崩溃和重启。

## 后果

隔离的 Electron 测试执行产品实际使用的代理配置、回环地址重定向、强制渲染器崩溃、释放和新视图创建，不启动 Harness。文件系统测试确认嵌套链接和会话根链接所指向的无关标记文件仍在。安装器预处理只检查宏展开，不编译安装器；编译后的实际卸载行为仍需发布验收。
